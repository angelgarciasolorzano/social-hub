# Global infrastructure, data and tooling

Code and configuration that belongs to no single module: global infrastructure, the morph map, media storage, seeders, test infrastructure, the frontend layout and tooling configuration.

> Moved from `CLAUDE.md` (SOC-78). Keep this document in sync with the code: update it in the same PR as any change to the module. `CLAUDE.md` keeps only the short orientation and the invariants that break things.

## Global infrastructure

**Global infrastructure (outside `app/Modules/`, SOC-42)** — code that serves several domains or the framework itself is not a module: Artisan commands live in `app/Console/Commands/` (auto-discovered, no provider needed; e.g. `MediaLibraryCleanFoldersCommand`), and shared classes that belong to no domain live in `app/Support/` (e.g. `app/Support/MediaLibrary/MediaLibraryCustomPathGenerator.php`, `app/Support/Translation/TranslatedText.php`, SOC-65, and `app/Support/Translation/FrontendTranslations.php`, SOC-67, below). MediaLibrary is a package integration used by Post and User, so it is not a domain module; its tests live in `tests/Feature/MediaLibrary/`.

## Morph map

The polymorphic map (`Relation::enforceMorphMap`) is registered in `App\Providers\AppServiceProvider::registerMorphMap()` (called from `boot()`) with keys: `user`, `post`, `like`, `comment`, plus the activity log subjects `admin_invitation` (`AdminInvitation::MORPH_NAME`), `trusted_device_event` (`TrustedDeviceEvent::MORPH_NAME`), `account_status_change` (`AccountStatusChange::MORPH_NAME`, SOC-35), `announcement` (`Announcement::MORPH_NAME`, SOC-61, owner of the banner image) and `role` (`App\Modules\Admin\Models\Role`, the module's subclass of Spatie's role, `AppServiceProvider::ROLE_MORPH_NAME`; SOC-70). `boot()` also calls `prohibitDestructiveCommandsInProduction()`.

## Media uploads and storage disks

Files are handled via `spatie/laravel-medialibrary` with a custom path generator (`app/Support/MediaLibrary/MediaLibraryCustomPathGenerator.php`, wired in `config/media-library.php`; Post media lives in `posts/{media id}/` and the rest, announcement images included, in `{media id}/`, so changing it would orphan stored files). The `app:clean-media-library-folders` command deletes everything under `storage/app/public` and `public/storage`, so it is prohibited in production (`MediaLibraryCleanFoldersCommand::prohibit()` in `AppServiceProvider::boot()`). Controllers catch `FileDoesNotExist|FileIsTooBig` and surface a flash notification via `back()->with('notification', [...])` or `Inertia::flash([...])->back()`. The notification shape is `{type: 'success'|'error', message: string, action?: {label, url}}`.

**Storage disks (SOC-62)** — MediaLibrary writes to `MEDIA_DISK` (default `public`). `config/filesystems.php` defines a dedicated `media` disk (driver `s3`, `visibility` public) with its own bucket and public URL (`MEDIA_S3_BUCKET`, `MEDIA_S3_URL`); its credentials and connection use `MEDIA_S3_ACCESS_KEY_ID`, `MEDIA_S3_SECRET_ACCESS_KEY`, `MEDIA_S3_DEFAULT_REGION`, `MEDIA_S3_ENDPOINT` and `MEDIA_S3_USE_PATH_STYLE_ENDPOINT` with `AWS_*` as fallback, the same pattern as `backups`, so images can live on another provider or account without touching the backups. `MEDIA_DISK=media` turns it on; the media disk never reads `AWS_BUCKET` or `AWS_URL`, which belong to the general `s3` disk that nothing uses today (nor does any code use `FILESYSTEM_DISK`). `.env.example` keeps the `AWS` block above the media and backup blocks because their credentials are `"${AWS_...}"` and phpdotenv only resolves variables already defined; variables coming from the platform instead of a `.env` file are not interpolated, and then the `config/` fallback applies. A local S3 emulator (LocalStack, MiniStack) needs `AWS_ENDPOINT=http://localhost:4566` and `AWS_USE_PATH_STYLE_ENDPOINT=true`. `.env.testing` defines no `MEDIA_DISK`, so tests stay on `public`. `tests/Pest.php` has `configWithEnvironment()` and `filesystemDiskWithEnvironment()` to evaluate `config/filesystems.php` with temporary environment variables (config() is already loaded in a test); they copy and restore the whole `$_SERVER`/`$_ENV` because rector-laravel rewrites single superglobal reads (even inside `unset()`) into invalid code. Tests: `tests/Feature/MediaLibrary/MediaDiskConfigurationTest.php` and `app/Modules/Admin/Tests/Backups/BackupConfigurationTest.php`.

## Seeders

`DatabaseSeeder` runs `UserSeeder` → `AdminAuthorizationSeeder` → `AdminUserSeeder` → `AdminCustomRoleSeeder` → `TrustedDeviceSeeder` → `AccountStatusSeeder` → `AnnouncementSeeder` → `PostSeeder` → `CommentSeeder` → `LikeSeeder` → `ActivityLogSeeder`. Counts are random and skewed (many low values, few high ones) through `App\Support\Seeding\SkewedRandom::count($min, $max, $skew)` (`mt_rand` based, `$skew` 1 is uniform): posts per user 0–50 (skew 3; 60% of the posts get a seeding image through `PostFactory::withImage(60)`), root comments per post 0–10 and replies per root comment 0–6 (skew 2), likes per comment 0–8 (skew 3, distinct users), devices per confirmed-2FA user 0–30 (skew 2). Choices with probabilities go through `App\Support\Seeding\WeightedRandom` (`pick($weights)` returns a key in proportion to its weight, `chance($percent)` is a yes/no draw). Every comment, root or reply, draws its own random author (`CommentSeeder::createComments()`; before, all root comments of a post shared one author); replies keep the single-level thread and the mention of another reply author. About 10% of the comments are marked edited (`edited_at` after `created_at`) and about 10% of the root comments that have replies are deleted, which leaves tombstones (SOC-52). `UserSeeder` creates 200 users (constructor argument `$userCount`) with exact shares in random order: 25% with `UserFactory::twoFactorConfirmed()`, 5% with `twoFactorPending()` (a real TOTP secret and eight Fortify-format recovery codes) and the rest without 2FA; half of them, drawn with `WeightedRandom::chance()`, get a random seeding profile picture and cover image through `UserFactory::withImages()`. Angel (`UserSeeder::TEST_USER_EMAIL`) is created last, never with 2FA, so the local login does not ask for an OTP; seeded 2FA secrets are random, so those users are for browsing screens, not for signing in. Angel is created with `forceCreate` because `email_verified_at` is not mass assignable. `TrustedDeviceSeeder` follows the SOC-45 rules and has no fixed scenarios: every confirmed-2FA user gets a random number of devices and each device picks its state with weights (active 45%, expiring soon 10%, expired 25%, revoked 20%) through the `TrustedDeviceFactory` states `active()`, `expiringSoon()`, `expired()` and `revoked()`, plus the events that explain it, each dated after the previous one and with the device's own dates (`Created` when the device was created; an active device may also have `Renamed` 20%, `Renewed` 15% — its trust then runs 30 days from the renewal — or `Revoked` followed by `Reactivated` 10%, which leaves it active; a revoked device has `Revoked` at its `deleted_at`). A share of the users without 2FA (5%, constructor argument `$formerTwoFactorSharePercent`, never Angel) are the ones who disabled it and only have revoked devices with `RevokedAll` events; pending users and everyone else have none. `TrustedDeviceFactory` generates coherent devices (a `public const TRUST_LIFETIME_DAYS` of 30): about 40% mobile (15% of those tablets), iOS or Android for mobile and Windows, Mac or Linux for desktop, a browser that exists on that system (Safari only on Mac and iOS, Edge only on Windows), an OS version, a name and a user agent built from the same system and browser, so `DeviceDetector` reads the user agent as the stored system, browser, version and device type (checked in `TrustedDeviceFactoryTest`). Its default state keeps the old dates (expires in 30 days) so the many tests that use it do not change; the date-coherent states are for seeding. Seeder tests cannot rely on `mt_srand` (`UserFactory::withImages()` and `PostFactory::withImage()` pick an image with `array_rand`, which consumes the same `mt_rand` sequence, only when the unversioned seeding images exist, so the sequence differs between a local checkout and CI), so they assert ranges and properties over enough samples and never that a specific value occurs; that a count can be 0 is covered by `tests/Unit/Support/Seeding/SkewedRandomTest.php`. `ActivityLogSeeder` (`app/Modules/ActivityLog/Database/Seeders/`, SOC-56) runs last and derives the activity from what the other seeders created, so every record points to something real: `content.post_created` per post; `content.comment_created` (with `post_id`) or `content.comment_replied` (with `thread_comment_id`) per comment, plus `content.comment_updated` for edited ones and `content.comment_deleted` (`permanently` false) for tombstones; `likes.added` per like; a `trusted_devices.*` mirror per `TrustedDeviceEvent` with its own date, IP and user agent; per user, 0–20 logins (skew 2, most with their logout), a few anonymous failed logins on their account, occasional password changes and `auth.two_factor_confirmed` for confirmed 2FA; `admin.account_suspended` / `admin.account_reactivated` per `AccountStatusChange` with its real date and only `target_user_id`; the `admin.announcement_*` audit derived from the seeded announcements (see [Announcement](modules/announcement.md)); and Angel's `admin.bootstrapped` followed by an `admin.role_granted` (Angel as actor, no IP) for every role of the other administrators, plus 3 to 8 cataloged role permissions Angel revoked and later granted back (`admin.role_permission_revoked` then `admin.role_permission_granted`, the `Role` as subject, SOC-69), so every role ends with its seeded permissions. Because the content seeders create everything at seeding time, its dates are spread over the last 60 days (edits and deletions after their creation, never in the future) instead of copying the records' `created_at`, so the activity list and its date filter have variety; device mirrors keep their real dates. Web actions get a fake IP and user agent, properties use only allowed keys and never content, rows are inserted 1000 at a time through the `ActivityLog` model, and the seeder does nothing when `activity_log` already has rows, so running it twice does not duplicate. A full `migrate:fresh --seed` produces about 65 000 rows in three seconds. Tests live in `app/Modules/ActivityLog/Tests/Seeders/ActivityLogSeederTest.php`. `AccountStatusSeeder` (`app/User/Database/Seeders/`, SOC-35) picks, among accounts that are neither administrators nor Angel, about 3% to suspend (a row with a sample Spanish reason and a random seeded administrator, dated after the account's last device activity, with its active devices soft deleted at that date plus a `RevokedAll` event created through the factory) and about 3% of the accounts without trusted devices for a past suspension followed by a reactivation (constructor arguments `$suspendedSharePercent` and `$reactivatedSharePercent`). It never uses `AccountStatusService` or `TrustedDeviceEvent::record()`, so it writes no `activity_log` rows and `ActivityLogSeeder` still runs; it does nothing when `account_status_changes` has rows or nobody holds `admin`. Tests live in `app/User/Modules/AccountStatus/Tests/Seeders/AccountStatusSeederTest.php`.

## Test infrastructure

- **Ubicación:** crea las pruebas específicas dentro del módulo dueño: `app/Modules/{Domain}/Tests/` para los módulos ya migrados a la nueva arquitectura (Post, Comment, Like, ActivityLog y Announcement) y para el módulo del sistema Admin; en la arquitectura vieja, usa `app/{Domain}/Tests/` o `app/{Domain}/Modules/{Feature}/Tests/`. Reserva `tests/` para pruebas transversales/de infraestructura y las pruebas existentes; no agregues allí nuevas pruebas específicas de un módulo.
- Agrupa las pruebas modulares por responsabilidad (`Crud/`, `Lifecycle/`, `Listeners/`, `Queries/`, `Models/`, `Requests/`, `Resources/`, `Factories/` para factories y `Seeders/` para seeders; el módulo Admin conserva `Database/` para los suyos). Al agregar una carpeta nueva, regístrala en `phpunit.xml` y configura en `tests/Pest.php` el caso base/traits que necesite.
- `composer test` — clears config then runs the whole Pest suite **in parallel** (SOC-59): `php -d memory_limit=2G artisan test --parallel --passthru-php="'-d' 'memory_limit=1G'"`. Laravel creates one MySQL database per worker (`social-hub-testing_test_N`) and reuses it on later runs (`--recreate-databases` after changing migrations); paratest workers do not inherit the parent's `-d`, hence `--passthru-php`. To debug a failure run it serially with `php -d memory_limit=2G vendor/bin/pest --compact <path>`: a serial run of the whole suite (or of the ActivityLog module alone) does not fit PHP's default 128 MB. A test file without a `namespace` must not import a global class (`use LogicException;`): PHP ignores it with a warning that paratest workers turn into an `ErrorException`, aborting the run.
- Shared test helpers live in `tests/Pest.php` (SOC-67 added `translatedTextIn()`, `createUserPreferring()` and the catalog helpers `translationFileTexts()`, `flattenTranslations()`, `translationPlaceholders()` and `translationFilesIn()`, shared by the admin and settings parity tests; SOC-59 added `invalidOtpFor()`, `grantAdminPermissionThroughTestRole()`, `storeBackupArchive()`, `createAdminInvitationWithToken()` and `withTemporarySeedingImages()`). Factories never attach seeding images unless asked (`UserFactory::withImages()`, `PostFactory::withImage(int $chancePercent = 100)`), so `createUser()`/`createPost()` have no media and write nothing to the public disk; tests that run `UserSeeder` or `PostSeeder`, which do attach them, call `Storage::fake('public')` first. The seeding images are not versioned, so a factory test that needs them uses `withTemporarySeedingImages()`.

## Frontend layout (`resources/js/`)

- `app/app.tsx` — Inertia + React entrypoint.
- `modules/<domain>/...` — feature pages/components mirrored to PHP domains (`auth`, `home`, `post`, `comment`, `profile`, `setting`, `account`, `static`, `announcement`).
- `shared/` — reusable code:
  - `components/shadcn/ui/` — shadcn/ui primitives (style: `new-york`, base: `neutral`, see `components.json`). Includes `chart` (Recharts wrapper) for any chart blocks — use `ChartContainer` + `ChartConfig` with `theme: { light, dark }` for theme-aware segments.
  - `components/`, `hooks/`, `lib/`, `types/`, `assets/`. `lib/dateTime.ts` holds the date helpers every module uses (`formatLongDate`, `formatShortDate`, `formatFullDate`, `formatActivationDate`, `formatActivationTime`, `formatTimeUntil`, `fromNow`, `valueOrNow`): components get them from `useDateTime()` (SOC-67), which binds them to the active language and the `dates` catalog, instead of calling `dayjs(...).format(...)` with a literal format. `lib/translation.ts` and `hooks/useTranslation.ts` are the translator (see [Languages](i18n.md#application-soc-67)).
  - `wayfinder/` — auto-generated typed Laravel routes/controllers (do not edit; regenerated by Vite plugin in `vite.config.ts`; gitignored, so each environment regenerates it with `php artisan wayfinder:generate --with-form --path=resources/js/shared/wayfinder`). Controller actions mirror the PHP namespace: migrated modules appear under `actions/App/Modules/<Domain>/…` (e.g. `@/shared/wayfinder/actions/App/Modules/Post/Controllers/PostController`), old-architecture domains under `actions/App/<Domain>/…`.
- `@/` alias resolves to `resources/js/` (configured in `tsconfig.json`).
- Real-time via `laravel-echo` + `@laravel/echo-react` against Laravel Reverb; broadcast channel defined in `routes/channels.php`.

## Tooling configuration

- `phpstan.neon` — paths `app`, `bootstrap`, `database`, `routes`; excludes `bootstrap/cache` and `app/Http/Middleware/HandleInertiaRequests.php`; scans `_ide_helper_models.php`; `configDirectories` lists `config`, `app/Auth/config` and `app/Modules/ActivityLog/config` (module config files may call `env()`).
- `.vscode/settings.json` — excludes `vendor/_laravel_ide/` from Intelephense: the Laravel extension generates stale model helpers there (e.g. `delete(mixed $id)` without its default), and `_ide_helper_models.php` already documents the models.
- `phpunit.xml` — `APP_ENV=testing`; database and test runtime settings are configured in `.env.testing`.
- `eslint.config.ts` — flat config with `typescript-eslint`, `eslint-plugin-react`, `eslint-plugin-perfectionist`, prettier integration.
- `.prettierrc` — import order puts `react`, `@inertiajs/react`, `react-icons` first, then `@/modules`, then shared (`@/shared/components`, `@/shared/hooks`, etc.), then relative.
- `vite.config.ts` — `laravel-vite-plugin` + `@inertiajs/vite` + `@vitejs/plugin-react` + `@rolldown/plugin-babel` (`reactCompilerPreset`) + `@tailwindcss/vite` + `@laravel/vite-plugin-wayfinder` (outputs to `resources/js/shared/wayfinder`).
