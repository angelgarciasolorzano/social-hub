# Activity log

Persistent record of user actions and the administrative audit (SOC-54, SOC-56), built on `spatie/laravel-activitylog` v5.

> Moved from `CLAUDE.md` (SOC-78). Keep this document in sync with the code: update it in the same PR as any change to the module. `CLAUDE.md` keeps only the short orientation and the invariants that break things.

**ActivityLog** (`app/Modules/ActivityLog/`) — persistent record of user actions and the administrative audit (SOC-54, part 1); `Contracts/`, `Console/Commands/`, `Database/Factories/`, `Enums/`, `Listeners/`, `Models/`, `Policies/`, `Providers/`, `Services/`, `Support/`, `Tests/`, `config/` (plus `Database/Seeders/ActivityLogSeeder`, described in [Seeders](../infrastructure.md#seeders)); namespace `App\Modules\ActivityLog\…`. Built on `spatie/laravel-activitylog` v5 (approved in SOC-54).

- **Storage decision** — one `activity_log` table, split by `log_name` (`auth`, `content`, `likes`, `trusted_devices`, `account`, `admin`), instead of one table per domain: volume is controlled by per-log retention, and the daily timeline of part 2 needs to query everything together. If one log (likes) ever grows too much it can move to its own table later, with real data to justify it. The package migration is published in the global `database/migrations/` (`2026_10_21_174837_create_activity_log_table.php`, integer ids, a `down()`, and the indexes `(log_name, created_at)` and `(causer_type, causer_id, created_at)`). `config/activitylog.php` keeps the package defaults except `include_soft_deleted_subjects => true`, so a comment tombstone still resolves as subject; buffering stays off.
- **Events catalog** — `Contracts/ActivityLogEvent` (an interface extending `BackedEnum`) is the orchestrator: it declares `eventName(): string` and `logName(): ActivityLogName`, and its constant `ENUMS` lists the per-domain enums in `Enums/Events/` (`ActivityLogAuthEvent`, `ActivityLogContentEvent`, `ActivityLogLikeEvent`, `ActivityLogTrustedDeviceEvent`, `ActivityLogAccountEvent`, `ActivityLogAdminEvent`; values `domain.action`, e.g. `auth.login`, `admin.role_granted`). PHP enums cannot share cases, hence one enum per domain. A new domain (SOC-35 suspensions, for instance) adds its enum there and registers it in `ENUMS`; `Tests/Contracts/ActivityLogEventTest.php` fails when an enum is not registered, and `Tests/Security/ActivityLogPrivacyTest.php` fails when a case is never recorded by a listener, command or service.
- **Writing** — `Services/ActivityLogger::record(ActivityLogEvent, ?Model $subject, ?Model $causer, array $properties)` is the only code that calls `activity()`: it derives the log from the event, always sets the causer (or `causedByAnonymous()`, so the package never guesses the user of another guard), adds `ip` and the `user_agent` (cut at 512 characters) only when a routed HTTP request is being handled, and throws `InvalidArgumentException` for the forbidden property keys `password`, `password_confirmation`, `current_password`, `token`, `token_hash`, `code`, `otp_code`, `recovery_code(s)`, `two_factor_secret`, `two_factor_recovery_codes`, `content` and `email`. A Pest `arch()` rule keeps `Spatie\Activitylog` inside this module. Writes are synchronous (no queue) so they share the caller's transaction.
- **What is recorded** — user actions go through domain events that other modules dispatch and `ActivityLogServiceProvider::registerListeners()` subscribes to: `AuthActivitySubscriber` (`Login`/`Logout` with their `guard`, `Failed` — subject the attempted account if it exists, anonymous causer, never the email —, `PasswordUpdated`, `PasswordReset` and the Fortify 2FA confirmed/disabled/recovery-codes events), `ContentActivitySubscriber` (`PostCreated`, `CommentCreated` — a reply keeps `thread_comment_id` and `replied_to_comment_id` —, `CommentUpdated` only when the text changed, `CommentDeleted` with `permanently`), `LikeActivitySubscriber` (`LikeToggled`, only when the state changed), `AccountActivitySubscriber` (account events above) and `TrustedDeviceActivityMirror` (`TrustedDeviceEventRecorded`, dispatched by `TrustedDeviceEvent::record()`; the subject is the `TrustedDeviceEvent` row, so factories and seeders, which do not go through `record()`, mirror nothing). The new events live with their owners: `App\Auth\Modules\Password\Events\PasswordUpdated`, `App\Auth\Modules\TrustedDevice\Events\TrustedDeviceEventRecorded`, `App\Modules\Post\Events\PostCreated`, `App\Modules\Comment\Events\*`, `App\Modules\Like\Events\LikeToggled` and `App\User\Events\*`; `LoginRequest` now dispatches Laravel's `Failed` with only the email. The administrative audit calls `ActivityLogger` directly inside its transaction: the three Admin commands (see [Admin commands](admin.md#admin-commands)) and `AdminInvitationService` (`issue()` records the inviter, the invitation and `target_user_id`, never the email or token; `accept()` records the resulting user, `account_created` and `roles_assigned`) `AccountStatusService` (suspensions and reactivations, SOC-35) and `AnnouncementService` (SOC-61). A rejected action records nothing.
- **Privacy** — never content, passwords, codes, secrets, tokens or emails: only ids, the names of changed attributes, the guard and the request's IP and user agent (kept to investigate incidents, deleted with the record). A deleted account or a permanently deleted comment keeps its id as subject/causer until the purge.
- **Retention and purge** — `app/Modules/ActivityLog/config/activity-log.php` (merged as `module.activity_log`, listed in `configDirectories` of `phpstan.neon`) sets the days per log through `SOCIALHUB_ACTIVITY_LOG_<LOG>_RETENTION_DAYS` (defaults: auth 180, content 365, likes 30, trusted_devices 180, account 365, admin 730); `ActivityLogName::retentionDays()` reads it. `activity-log:purge` (`Console/Commands/ActivityLogPurgeCommand`, registered only in console) validates every retention and deletes each log through the package's `CleanActivityLogAction`; it is scheduled daily at 03:30, after `trusted-devices:purge`. The package's own `clean_after_days` is unused.
- **Model, policy and labels (SOC-56)** — `Models/ActivityLog` extends Spatie's `Activity` and `config/activitylog.php` points `activity_model` to it, so the package writes, purges and reads through the module's class and the `arch()` rule keeps holding (Admin uses this model, never Spatie's). It adds the scope `involvingUser(User)` (the user is the causer or the subject, matched by morph type and id) and `#[UseFactory(ActivityLogFactory::class)]` (default state: an anonymous `content.post_created`; states `forEvent()`, `causedBy(User)` and `performedOn(Model)`, for tests only — application code records through `ActivityLogger`). `Policies/ActivityLogPolicy`, attached with `#[UsePolicy]` like `UserPolicy`, allows `viewAny` with `admin.activity.viewAny` and `view` with `admin.activity.view`, and denies `create`, `update`, `delete`, `deleteAny`, `restore` and `forceDelete` to everyone. `Support/ActivityLogEventCatalog` turns stored values into readable names from the registered enums: `find()`, `label()` (the case name as a headline, e.g. 'Password Updated', or the raw value for an event no longer cataloged), `logLabel()`, `eventOptions()` (grouped by log) and `logOptions()`.
- Out of scope until part 2: visited pages, a daily timeline or charts, React UI interactions and security emails.
